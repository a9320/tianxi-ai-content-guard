# 判读与报告指引

## 引擎优先原则

`verdict` / `counts` / `coverage` 全部由引擎确定性产出，你的工作是**解释**：
把 `top_findings` 的每一条翻译成用户能懂的"危害 + 为什么 + 怎么办"。
你与引擎意见不一致时，报告保留引擎结论，可附一句你的观察，不得改判。

## 逐条呈现模板

```text
[严重度] 规则名（PITAX 编号）— 位置
  危害：这条命中意味着什么（按 references/rules.md 卡片口径）
  证据：（引用 evidence_redacted，一字不改）
  建议：（advice 原文或按卡片建议扩展）
```

## 用户质疑误报时

1. 先给出引擎口径：该规则的触发条件与置信度（卡片可查）；
2. 如命中属于"提及而非指令"（安全研究/教学语境引用了攻击短语），如实说明
   确定性层无法区分语义意图，建议用户自行判断是否在可信上下文中；
3. 不悄悄降低严重度，不改输出文件。

## SARIF / CI

仓库模式可加 `--sarif <路径>` 导出 SARIF 2.1.0（可接 GitHub Code Scanning）；
`--fail-on critical|high|medium` 供 CI 用（命中则退出码 1）。

## 报告落盘说明

命中 >10 条时引擎自动在系统临时目录写 `report.jsonl`（逐条脱敏）与
`summary.md`（人读摘要），路径在信封 `report_path` / `summary_path`。
需要向用户展示更多明细时，你分页读取这些文件，而不是让用户自己找。
